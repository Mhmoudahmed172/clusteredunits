# منصة منتجات الوحدات الإنتاجية العنقودية في قطاع غزة (HCC Platform)

**مشروع الدعم العاجل لتعافي المنشآت الصناعية في غزة من خلال الوحدات الإنتاجية العنقودية**
- **تمويل:** وزارة الخارجية النرويجية (Norwegian MFA)
- **إشراف:** وزارة الاقتصاد الوطني والاتحاد العام للصناعات الفلسطينية (PFI)
- **تنفيذ:** برنامج الأمم المتحدة الإنمائي (UNDP) ووحدة التجمعات الإنتاجية العنقودية (HCC)

---

## 1. نظرة عامة على المنصة

منصة ويب عربية متكاملة (Full-Stack RTL) تجمع بين البوابة العامة لاستكشاف المنتجات والتجمعات وطلب عروض الأسعار والتعاقد (`RFQ`)، ولوحة إدارة داخلية (`/admin`) لإدارة المحتوى والمنتجات والشرائح السعرية والتجمعات ومتابعة الطلبات والتقارير التحليلية.

### المزايا الرئيسية:
1. **الهوية البصرية الرسمية:** خط `Cairo`، اتجاه `RTL`، وألوان المشروع المعتمدة (`#0F253E` كحلي، `#C8A24B` ذهبي، `#1C4587` أزرق) مع الشعارات والأدوار الرسمية للشركاء.
2. **نقل واستيراد البيانات المرجعية:**
   - **14 منتجًا صناعيًا** (منها **4 منتجات تكاملية مشتركة**) مع كامل المواصفات الفنية وشرائح الأسعار الثلاث لكل منتج.
   - **15 تجمعًا إنتاجيًا عنقوديًا** موزعة على **6 قطاعات صناعية** مع المنشآت المستضيفة، المحطات المركزية، والمنشآت الأعضاء.
   - استخراج وحفظ الشعارات وصور المنتجات المضمّنة كملفات صور فعلية في `/public/uploads/extracted/`.
3. **نظام طلبات عروض الأسعار والتعاقد (`RFQ`):**
   - حساب لحظي للشريحة السعرية والسعر التقديري حسب الكمية والعملة (`USD` / `ILS`)، مع إعادة التحقق والحساب على الخادم.
   - حماية من تكرار الإرسال (`Idempotency`) وتوليد رقم مرجعي فريد لكل طلب (`RFQ-GZ-...`).
4. **لوحة الإدارة والتقارير (`/admin`):**
   - صلاحيات مبنية على الأدوار (`مدير النظام` و`محرّر`) مطبقة على الخادم.
   - رسوم بيانية تفاعلية (`SVG` مع تلميحات عند المرور): رسم خطي لتطور الطلبات أسبوعيًا/شهريًا، رسم أعمدة لتوزيع الطلبات حسب القطاع الأساسي (مع ربط المنتجات التكاملية بقطاع تجمعها الحاضن)، ورسم دائري لتوزيع الحالات.
   - تصدير التقارير والطلبات بصيغة `CSV (UTF-8 BOM)` متوافقة مع اللغة العربية.

## 2. تهيئة قاعدة البيانات واستيراد البيانات

تعتمد المنصة على قاعدة بيانات **SQLite** مدمجة (`node:sqlite`) تُحفظ تلقائيًا في المسار `./data/gaza_clusters.db`.

- **التهيئة التلقائية عند التشغيل:** عند تشغيل الخادم (`npm run dev` أو `npm start`)، يقوم النظام تلقائيًا بإنشاء الجداول وتشغيل دالة الاستيراد الآمن `seedDatabase()` في `src/server/db.ts`.
- **قابلية إعادة التشغيل (Idempotency):**
  - يتحقق الاستيراد من وجود السجلات قبل الإدراج.
  - لا يكرر أي منتج أو تجمع أو منشأة عند إعادة التشغيل.
  - يحافظ على أي تعديلات أجرتها الإدارة (`updated_by_admin = 1`) ولا يكتب فوقها.
  - تبدأ قاعدة البيانات بـ **0 طلبات عروض أسعار (RFQ)** لتعكس التقارير البيانات الفعلية المدخلة.
- **إعادة الاستيراد من داخل اللوحة:** يمكن لمدير النظام أو المحرّر الضغط على زر «تشغيل فحص واستيراد البيانات الآمن» من تبويب «القطاعات والمنشآت والاستيراد» في لوحة الإدارة.

## 3. إعداد حسابات الإدارة الأولية (بيانات الدخول)

يتم إنشاء حسابي إدارة افتراضيين عند التهيئة الأولى لقاعدة البيانات:

| الدور / الصلاحية | البريد الإلكتروني | كلمة المرور | الصلاحيات |
| :--- | :--- | :--- | :--- |
| **مدير النظام (System Admin)** | `admin@pfi-gaza.ps` | `Admin@2025` | إدارة المستخدمين، الإعدادات العامة، المحتوى، والطلبات والتقارير |
| **محرّر (Editor)** | `editor@pfi-gaza.ps` | `Editor@2025` | إدارة المنتجات، التجمعات، الصفحة الرئيسية، ومتابعة طلبات RFQ |

---

## 4. المتغيرات البيئية (`.env`)

يمكن تخصيص الإعدادات عبر ملف `.env` انطلاقًا من `.env.example`:

```env
DATABASE_PATH="./data/gaza_clusters.db"
INITIAL_ADMIN_EMAIL="admin@pfi-gaza.ps"
INITIAL_ADMIN_PASSWORD="Admin@2025"
INITIAL_EDITOR_EMAIL="editor@pfi-gaza.ps"
INITIAL_EDITOR_PASSWORD="Editor@2025"
INITIAL_EXCHANGE_RATE="3.1"
```

## 5. أوامر التشغيل والبناء

- **تشغيل بيئة التطوير (الخادم + الواجهة على المنفذ 3000):**
  ```bash
  npm run dev
  ```
- **فحص الأنواع والبرمجة (TypeScript Lint):**
  ```bash
  npm run lint
  ```
- **بناء نسخة الإنتاج:**
  ```bash
  npm run build
  ```
